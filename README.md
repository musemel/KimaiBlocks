# Kimai Blocks

<img src="Assets/KimaiBlocks.png" width="96" alt="Kimai Blocks icon">

Kimaiの実績を5分刻みのタイムブロックで管理する、Windows向け非公式クライアントです。C# / WPF / .NET 10で実装しています。

## 主な機能

- 週カレンダーで実績を作成・ドラッグ移動・サイズ変更。未来の実績も入力可能
- プロジェクトの検索・表示選択、アクティビティツリー、お気に入り、フォルダ分類
- 週・日の簡易集計と、コメント別／プロジェクト別に展開できる詳細集計ダイアログ
- 休日・休み時間・時間外の暗色表示・入力禁止、土日の表示切り替え
- 起動時の自動接続、定期保存、終了時保存、未保存変更のキャッシュ
- グローバルアクティビティを有効にしたプロジェクトの追加

## 必要環境

- WindowsでWPFを実行できる環境
- 開発時: .NET 10 SDK
- 実行時: .NET 10 Desktop Runtime
- アクセス可能なKimaiサーバーと、そのユーザーのAPIトークン

Kimai 2.67.0で基本的な実績CRUDを確認しています。すべてのバージョンや独自設定との互換性を保証するものではありません。

## ビルドと起動

リポジトリのルートでPowerShellを開きます。

```powershell
./Build.ps1
./dist/KimaiBlocks.exe
```

初回ビルドにはNuGetからの依存パッケージ取得が必要です。実行ファイルだけでなく、`dist` フォルダ全体を配布してください。ビルド済みバイナリはこのソース一式には含まれません。

初回起動時の設定画面で「追加」からアカウントを登録し、一覧で選択して保存・接続します。複数アカウントや複数サーバーを登録できます。通常のログインパスワードは使いません。次回から保存した設定で自動接続します。

## 操作・設定

詳しくは [操作ガイド](docs/USAGE.md) を参照してください。

保存間隔は既定60秒です。保存失敗時は変更を保持し、通常の終了を中止します。HTTP接続は設定で明示的に許可した場合のみ使用できます。

接続設定とキャッシュは `%LOCALAPPDATA%/KimaiBlocks` に保存されます。APIトークンはAES-GCMで暗号化し、鍵は同じフォルダの `token.key` に保存します。実績キャッシュは平文です。このディレクトリをリポジトリへ追加しないでください。

## 必要なKimai権限

管理者である必要はありません。ロールはサーバーでカスタマイズできるため、権限名で確認してください。

| 用途 | 権限・条件 |
| --- | --- |
| API接続 | `api_access` と有効なAPIトークン |
| 自分のトークン発行 | `api-token_own_profile`（Kimaiのプロフィール画面） |
| 自分の実績の参照・作成・編集・削除 | `view_own_timesheet`, `create_own_timesheet`, `edit_own_timesheet`, `delete_own_timesheet` |
| プロジェクト追加 | `create_project`、追加先の顧客にアクセスできること |
| 一覧や登録先の利用 | Kimaiのチーム割当・プロジェクト／顧客／アクティビティの公開範囲で対象にアクセスできること。サーバーで一覧・管理機能が制限されている場合は `view_project`, `view_activity`, `view_customer` も確認 |

請求対象は操作画面を設けずAPIにも送信しません。既存の値は維持し、新規作成はKimaiの既定値に従います。通常の実績保存で請求対象・単価・エクスポート・他人の実績の編集権限は不要です。未来入力・締め期間・プロジェクト期間などのサーバー側制約は権限とは別に適用されます。
参照: [公式の権限一覧](https://www.kimai.org/documentation/permissions.html)、[実績の権限](https://www.kimai.org/documentation/timesheet.html)、[チーム](https://www.kimai.org/documentation/teams.html)。

## 設定の移行と配布

アプリを終了し、`%LOCALAPPDATA%\KimaiBlocks` **全体**を移行先の同じ場所へコピーしてください。`connection.json`、`token.key`、各アカウントのキャッシュが対象です。移行先の既存フォルダは必要なら別途バックアップしてください。

鍵はPCやWindowsユーザーに依存しません。**このフォルダと鍵を入手した人はトークンを復号できます**。移行データは認証情報として扱ってください。旧DPAPI形式は元のWindowsユーザーで新版を一度起動すると移行されます。旧形式を先に別PCへコピーした場合はAPIキーの再入力が必要です。APIキーはアカウント編集画面では表示され、一覧ではマスクされます。

EXEの隣の `defaults.json` に `Url`, `SaveSeconds`, `CatalogMinutes`, `UpdateFolder`, `Calendar` を指定できます。**初回起動のみ**に適用し、既存のAppData設定は上書きしません。APIキーやユーザー別情報は入れないでください。HTTP許可は利用者が明示的に設定します。

```json
{
  "Url": "https://kimai.example.com",
  "SaveSeconds": 60,
  "CatalogMinutes": 60,
  "UpdateFolder": "C:\\CompanyApps\\KimaiBlocks",
  "Calendar": {
    "DaysOff": [0, 6],
    "Holidays": "",
    "Breaks": "12:00-13:00",
    "OffHours": "00:00-09:00\n18:00-24:00",
    "Shade": true,
    "BlockInput": false
  }
}
```

「設定」のアップデート確認フォルダにはローカルフォルダまたはUNCパスを指定します。配布側はビルドした **dist一式**をその場所へ配置します。起動時とメニューから `KimaiBlocks.dll` と `KimaiBlocks.exe` のファイルバージョンを確認し、読み取れた新しい方を現在のバージョンと比較します。DLLがないランタイム同梱の単一EXE配布にも対応し、新版があれば通知します。実行・インストール・ファイル置換は自動では行いません。確認はバックグラウンドで行い、8秒で待機を打ち切ります。起動時に確認できなかった場合は通知せず、メニューの手動確認でエラーを確認できます。空欄で無効です。

バージョンは `年.月.日.時分`（日本時間）です。例: `2026.9.27.549` は2026年9月27日05:49更新。変更時に `KimaiBlocks.csproj` の `Version` を更新してください。同じ分に複数版を配布する場合は次の分の値など、より大きな値にします。

## サーバー実績集計（全ユーザー）

「メニュー → サーバー実績集計（全ユーザー）」で開始日・終了日または全期間を選び、「取得して集計」を押します。表示週を初期期間にします。サーバー保存済みの実績を読み取り専用で取得し、ローカルの未保存変更は含めません。請求情報は表示しません。

| テーブル | 主な表示 |
| --- | --- |
| ユーザー入力状況 | 有効状態、実績件数、開始日基準の入力日数、時間、計測中件数、時間不明件数、最初／最後の開始日時 |
| プロジェクト合計 | 閲覧可能な全ユーザーの件数・人数・時間 |
| プロジェクト×ユーザー | プロジェクト内のユーザー別件数・時間 |
| プロジェクト×アクティビティ | プロジェクト内の作業別件数・人数・時間 |
| 実績明細 | 実績ID、プロジェクト、ユーザー、作業、開始／終了、時間・秒数、状態、コメント |
| アクティビティ別 | 作業ごとの横断集計 |
| 月別 | 開始月ごとの件数・人数・時間 |
| プロジェクト×コメント | プロジェクト内の同じコメントごとの件数・人数・時間 |

列見出しで並べ替え、検索欄で表示中のテーブルを絞り込み、行選択してCtrl+Cで表をコピーできます。検索は表示行を絞るもので、合計を再計算する条件ではありません。

### 取得範囲と権限

他人の実績には `view_other_timesheet` と対象へのチームアクセス権が必要です。ユーザー一覧には `view_user` が必要です。`api_access` も引き続き必要です。ロール名から権限を推測せず、APIが許可した結果を使います。

Kimai 2.67では `user=all` を指定しても他人の実績権限がない場合は本人分だけが返されます。したがって画面には「閲覧を許可された範囲」と明記します。ユーザー一覧が403の場合は本人と取得実績内のユーザーIDで表示します。0件は「取得0件（未入力とは断定不可）」であり、未入力者・欠勤者の確定一覧ではありません。入力日数も勤務予定や入力完了を判定するものではありません。

期間は接続ユーザーのタイムゾーンで**開始日時**に適用し、終了日の23:59:59を含みます。期間外に開始した実績は含まず、期間内に開始して期間外に終了した実績は全時間を集計します。全期間は日付条件を付けません。時間はKimaiの `duration` 秒を集計し、休憩を再控除したり5分に丸めたりしません。計測中・duration不明は件数に含め、時間合計からは除外します。サーバーに登録された重複・未来の実績も対象です。

取得中は進捗を表示しキャンセルできます。ページを順番に取得し、通信失敗・取得上限（50万件）・ページ取得が進まない場合は部分集計を表示しません。集計データはこのダイアログのメモリ上だけに保持します。取得中に他のユーザーが更新した場合、同時点のスナップショットにはならないため必要に応じて再取得してください。

参照: [Kimaiの実績APIと権限制御](https://github.com/kimai/kimai/blob/2.67.0/src/API/TimesheetController.php)、[ユーザー一覧API](https://github.com/kimai/kimai/blob/2.67.0/src/API/UserController.php)。

## 時間外・コメント集計

「メニュー → 休日・休み時間・時間外」で毎日の時間外を複数行で指定できます。5分刻みで `00:00-09:00`、`18:00-24:00` のように指定します。日をまたぐ区間は午前・午後に分けてください。空欄なら時間外の制限はありません。暗色表示・入力禁止は休日・休み時間・時間外に共通して適用します。既存実績は消さず、入力禁止は新規・移動・時間変更に適用します。

配布用 `defaults.json` の `Calendar` でも指定できます。添付の初期値は土日休み、休憩12–13時、時間外0–9時／18–24時、暗色表示あり・入力禁止なしです。`DaysOff` は0=日曜〜6=土曜。既存のAppData設定を優先するため、旧版の利用者の時間外は空欄のままです。設定画面から追加してください。

右パネルは「週」「日」タブで集計を切り替え、下部で選択実績を編集できます。日集計はプロジェクト → コメントの階層 → アクティビティ → 実績のツリーで内訳を確認できます。プロジェクトとコメントは初期状態で展開し、折りたたみも可能です。詳細は「コメント別の詳細集計」から開き、週全体／日別を切り替えます。

- プロジェクト → コメントの階層 → アクティビティ → 実績
- `aaa/xxx` と `aaa/yyy` は `aaa` の下に `xxx` と `yyy` を表示します。別プロジェクトのコメントはまとめません。

各階層に合計時間・件数を表示します。空のコメントは「コメントなし」にまとめます。前後の空白と改行コードを揃えて比較し、それ以外の表記差は別グループにします。未保存・未来・非表示曜日の実績も含む表示週の集計で、重複時間も加算します。

## 選択・編集・表示操作

- Ctrl+クリックで個別に追加／解除、Shift+クリックで時刻順の範囲選択。青い枠と光彩、右下の件数で選択を確認できます。選択した複数ブロックをまとめて移動・サイズ変更・Ctrlドラッグコピーできます。Ctrlコピーのプレビュー中も元のブロックを残します。
- 右下でプロジェクト・作業・日付・開始時刻・時間・コメントを編集し、「適用」で保存待ちにします。複数選択時はコメントを一括変更できます。入力中は定期保存を待機します。
- ダブルクリック／Enterの詳細編集はコメントにフォーカス。F2でブロック上のコメント編集、Enterで確定、Ctrl+Enterで改行、Escapeでキャンセルします。コメント編集を抜ける際も適用します。
- ツリーから既存ブロックへドロップすると、時間・コメントを維持してプロジェクトとアクティビティを置き換えます。空き位置へのドロップは新規作成です。
- 新規・コピー・時間変更時に、他の実績や入力禁止時間を除いて5分単位で切り詰め・分割します。全区間が使用済み・禁止なら操作全体を中止します。既存実績を一括修正することはなく、時刻を変えないコメント・作業編集でも既存の時間を維持します。
- 左右パネルの境界をドラッグして幅を変更できます。Ctrl+ホイール／メニューの倍率で50～400%に拡大縮小。幅・倍率は保存します。初期設定では土日列を隠し、既存の表示設定は引き継ぎます。
- 作業ツリーのプロジェクト名は `/` 区切りで階層化します。アクティビティ名は設定した正規表現の $1 でまとめ、$2 を表示します（下記参照）。実際のKimaiの名前は変更しません。
- 自動色はプロジェクト名から決まります。標準16色・256色・無制限を選択できます。固定色は優先します。詳しくは下記「安定した自動色」を参照してください。

| キー | 操作 |
| --- | --- |
| Ctrl+S | 右下の入力を適用してサーバーへ保存 |
| Ctrl+Z | 元に戻す |
| Ctrl+Y / Ctrl+Shift+Z | やり直す |
| Ctrl+A | 表示中の実績を全選択 |
| Ctrl+C / Ctrl+V | 選択実績をコピー／クリックしたカレンダー位置へ貼り付け |
| Delete | 選択実績を確認して削除 |
| Enter / F2 | 詳細編集／ブロック上のコメント編集 |
| Escape | 選択解除（コメント編集中はキャンセル） |
| Ctrl+＋ / Ctrl+－ | 拡大／縮小 |

テキスト入力中のCtrl+Z・Ctrl+C等はテキスト編集に使います。Undoは直近100操作まで、定期保存後も対応します。保存済みの削除を戻す場合は同じ入力内容の実績を新規作成するため、実績IDなどサーバー管理情報は元と同一にはなりません。週変更・再読込・アカウント変更では履歴をクリアします。保存結果が不明な間はUndoを含む編集を止めます。

### 他メンバーの表示

「サーバー実績集計」で期間を取得後、「メンバーを選択」で検索付きチェックリストから対象を選びます。選択したメンバーだけで全テーブルを再集計します。全解除は0人で、全員には戻りません。フィルタは取得済みデータに適用し、追加のAPI通信は行いません。

「日／週のブロック表示」では、1日をメンバーごとの列で比較するか、1週間をユーザー切替で閲覧できます。重複実績は横に並べ、日またぎは日ごとに分割表示します。日付／ユーザー／倍率を切り替えられ、土日表示は本体設定に従います。ヘッダーは固定し、人数が多い場合は横スクロールできます。閲覧専用で、自分の編集対象とは分離しています。

表示できるのは取得した期間・権限範囲内の実績です。開始日時が取得期間より前の実績は取得対象外です。枠の高さは開始～終了の経過時間、表の集計はKimaiのdurationです。計測中は仮の5分枠を表示し、確定時間には加えません。

## 新しい操作

- 実績ブロックの表示順はプロジェクト名 → コメント → 時間 → アクティビティです。収まる範囲で表示し、全文・実績ID・操作案内はマウスを重ねたポップアップで確認できます。

- 初回取得・新しく見つかったプロジェクトは表示チェックなし。既存の表示選択は保持します。「すべてのチェックを外す」は検索条件に関係なく全件が対象です。
- プロジェクト・作業ツリー検索は全半角カナ、ひらがな／カタカナ、英字大小、スペースの差を無視します。誤字の推測はしません。
- 現在時刻はカレンダーに赤い線のみ、メニューの左に日時を表示します。接続ユーザーのKimaiタイムゾーンで毎秒更新します。赤い線は表示範囲内の日だけに表示します。
- グローバルアクティビティが無効（または有効と確認できない）なプロジェクトには、専用アクティビティのみ表示します。
- 保存エラー画面で「未保存変更を破棄」を選べます。確認後に残ったローカル変更をキャンセルし、終了時なら終了できます。すでにサーバーが受け付けた操作は巻き戻しません。使い続ける場合は再読込してください。
- メニュー「バックアップを破棄してサーバーから再取得」は現在のアカウントの未保存変更・実績バックアップ・一覧キャッシュを破棄し、表示週を取得します。取得に失敗した場合は未保存変更を保持します。表示選択・フォルダ・アカウント設定は保持します。

## 開発・テスト

```powershell
dotnet build -c Release
dotnet ./bin/Release/net10.0-windows/KimaiBlocks.dll --self-test
```

`--self-test` は模擬HTTP通信を使い、実サーバーを変更しません。対話可能なWindowsデスクトップでは `--sync-test` で保存周期・終了制御も検証できます（テスト用ウィンドウが開きます）。

| ファイル | 内容 |
| --- | --- |
| App.cs / Sidebar.cs / Statistics.cs | カレンダー・ツリー・統計UI |
| Connection.cs / PendingQueue.cs | 接続・定期保存・終了制御 |
| KimaiService.cs / CatalogCache.cs | APIクライアント・一覧キャッシュ |
| CalendarRules.cs / ProjectCreation.cs | 休日設定・プロジェクト追加 |

GitHub ActionsでWindows上のビルドと `--self-test` を実行します。実サーバーの認証情報や専用のセットアップスクリプトは含めていません。

## 現在の制限

- ドラッグ中の自動スクロールは未実装
- 計測中、エクスポート済み、休憩付き、日またぎ、5分単位以外の実績は読み取り専用
- 統計はブロック時間の合計。正確な請求時間や休憩控除はKimaiで確認
- 保存前の競合確認は行いますが、サーバーとの完全な排他制御はありません

### アクティビティ一覧の正規表現による分類

「メニュー → 表示・作業ツリー → 表示・分類設定」の「アクティビティの分類」で正規表現を指定し、保存すると反映されます。第1キャプチャグループ（$1）が一致する項目を同じ親にまとめ、第2グループ（$2）を子の表示名にします。分類は各プロジェクト内に適用します。

- 標準値 `(.*)/(.*)`：`aaa/xxx`、`aaa/yyy` → 親 `aaa` の下に `xxx`、`yyy`。
- この式は最後の `/` で区切るため、`aaa/bbb/xxx` → 親 `aaa/bbb`、子 `xxx`（親をさらに分割しません）。
- 最初の `/` で区切る場合は `^([^/]+)/(.*)$` を指定します。
- 空欄で分類を無効にします。マッチしない項目、$1または$2が空の項目は元の名前で表示します。
- 元の名前とKimaiのIDは変わらず、検索・お気に入り・ドラッグには元のアクティビティを使用します。
- 不正な式やキャプチャグループが不足する式は設定保存時にエラー表示します。マッチ処理が制限時間を超えた場合は残りを元の名前で表示します。

配布用 `defaults.json` の `ActivityGroupingPattern` でも指定できます（例：`"ActivityGroupingPattern": "(.*)/(.*)"`）。初回起動用の設定で、既存のAppData設定は上書きしません。既存設定に項目がない場合も標準値を使います。JSONでバックスラッシュを書くときは `\` とします。



### 表示と配置の操作

メニューは「接続・データ」「表示・作業ツリー」「作業・カレンダー」「集計」「更新・配布設定」に分かれています。アカウント設定、表示・分類設定、自動保存・キャッシュ・更新先、休日・休み時間・時間外はそれぞれ別のダイアログです。

- 上部の「土日」「日」「週」「入力ロック」でワンタッチ切り替えできます。青いボタンが有効な状態です。
- 「日」は選択実績・選択時間範囲・日集計の日を1列で表示します。左右の移動ボタンで前日・翌日に移動します。「週」で週表示に戻ります。
- 入力ロックは休日・休み時間・時間外に適用します。既存実績は変更せず、新規作成や移動・時間変更時に入力可能な時間へ分割・調整します。
- カレンダーの空き部分を縦にドラッグして時間範囲を選択してから、左のアクティビティをドラッグすると、その日時・長さで配置します。別の空き部分をクリックすると時間範囲を解除します。
- プロジェクトや分類済みアクティビティの親をカレンダーへドラッグすると、検索可能な一覧からアクティビティを選んで配置できます。プロジェクトをフォルダへドラッグする従来の操作も使えます。
- 左の子項目は低い1行表示とし、長い名前は省略します。カーソルを合わせると全文を表示します。
- 選択実績は影を使わず青枠で表示します。ブロック内に全文が収まる場合はコメントを最後に置き、小さい場合はプロジェクト・コメントを優先します。
- プロジェクトの右クリック →「このプロジェクトの色…」で、Windows標準の色選択ダイアログから固定色を指定できます。「色を自動割当に戻す」も右クリックで選べます。メニューから開く色設定ではHEX入力も使えます。
- 無効と確認できたユーザー・プロジェクト・アクティビティは集計から除外します。無効なプロジェクト・アクティビティは作業一覧・カレンダーにも表示しません。サーバーの実績自体は削除しません。権限により状態を取得できない対象は無効と断定せず表示します。

左ツリーのフォルダ追加は「未分類」またはフォルダの右クリックから行います。プロジェクトの右クリックは色設定のみ、アクティビティとその分類見出しにはメニューを表示しません。ユーザー入力状況の表では、有効・無効の列を省略しています。



### 安定した自動色

「表示・作業ツリー → プロジェクトの固定色」の上部で固定16色（標準）、固定256色、無制限から選択します。自動色はプロジェクト名をもとに決まり、IDや表示順、表示対象の増減には依存しません。同名のプロジェクトは基本的に同じ色になります。

無制限では「既存色と重なる場合は近縁色を割り当てる」を有効にできます。重複時の割当はアカウントのキャッシュに保持し、ほかの項目の表示変更で色が揺れないようにします。「自動色の設定を保存して再設定」は選択した設定を保存して自動色だけを再計算し、手動で固定した色は維持します。16色・256色では重複を許容します。

配布用 defaults.json でも `ProjectPalette`（16、256、0=無制限）と `AvoidColorCollisions`（true/false）を指定できます。

### 常設の管理設定

EXEの隣に **settings.policy.json** を配置すると、指定された項目だけを起動中の実効設定として使い、設定画面では編集不可にします。対象は更新フォルダとアクティビティ分類の正規表現です。

```json
{
  "UpdateFolder": "\\\\server\\apps\\KimaiBlocks",
  "ActivityGroupingPattern": "(.*)/(.*)"
}
```

どちらか一方だけの指定も可能です。空文字も管理値として有効です。ファイルは削除せず、個人設定に上書き保存もしません。ファイルやキーを取り除いて再起動すると、その人の元の設定を使います。形式が不正な場合はエラーを通知し、通常設定で起動します。更新時はEXEなどと一緒に配布・コピーしてください。配布元からの自動取り込みは行いません。

旧 settings.override.json / settings.override.pending.json の適用・削除・更新時の取り込みは廃止し、残っていても無視します。以前の版ですでに個人設定へ保存された値は元に戻しません。docs/settings.policy.example.json を必要な値に編集して利用できます。

### フォルダと表示操作

- フォルダの右クリックからサブフォルダ追加、名前変更、上下の並べ替え、最上位への移動ができます。フォルダを別フォルダへドラッグして階層を変更できます。循環する移動はできません。
- フォルダを削除すると子フォルダと所属プロジェクトは一つ上へ移動します。個別作業へのリンクは解除されますが、Kimaiの作業・実績は削除しません。
- 個別のアクティビティをフォルダへドラッグするか「表示する作業を選択…」で、その作業だけを登録できます。登録解除は同じ選択画面でチェックを外します。リンクした作業は、表示プロジェクトのチェックにかかわらず利用できます。
- お気に入りはツリー先頭に常設し、プロジェクトや分類の階層を挟まず一覧表示します。表示プロジェクトのチェックにかかわらず、有効なお気に入り作業を表示します。追加・削除・移動は不要です。
- 左ツリーのプロジェクトや分類は初期状態で閉じ、利用者が開閉した状態を保存します。罫線で階層を示します。
- メニュー横の保存・再読込ボタンはなくし、上部のアイコンから操作します。
- 実績の新規作成・コピー後、引き伸ばしによるコピー・分割後は選択を解除します。Ctrlを押して上下端をドラッグすると、元の実績を残して伸ばした先の空き時間へコピーします。
- 選択中の実績は、同じプロジェクト・同じコメントを持つブロックの日合計と週合計を右の編集欄上部に表示します。複数選択時は最大6種類まで表示します。
- 時間目盛りは文字が重ならない間隔で60／30／15／10／5分に切り替わります。Ctrl+ホイールは連続した倍率変更をプレビューし、操作が止まってから画面と設定を確定します。


フォルダのドラッグでは、移動先の中央にドロップするとその中へ移動し、上端・下端へのドロップで前後に並べ替えます。「未分類」へのドロップで最上位へ戻せます。土日・日・週の切り替えは上部ボタンに統一しました。既存のお気に入り一覧フォルダは常設のお気に入りに統合します。子フォルダ・個別作業などを持つ旧フォルダは通常フォルダとして残します。


### プロジェクト選択と色の確認

実績の詳細編集と右側の編集欄では、プロジェクト選択欄へ名前を入力すると候補を絞り込めます。全角・半角カナ、ひらがな・カタカナ、スペースの有無を吸収して検索します。候補を選択してプロジェクトを確定してください。検索文字そのものをプロジェクト名として保存することはありません。

プロジェクトの固定色ダイアログには、各プロジェクトの色見本と「自動／固定」、現在の色コードを表示します。自動色の再設定や固定色変更後も一覧を更新します。左ツリーは見出しを動かさず、展開した子項目を下に字下げして表示します。

### 履歴・定型入力と期間表示（2026-10-06）

- 左パネルを「作業」「履歴」「定型」のタブで切り替えます。「履歴」は同じプロジェクト・作業・コメント・長さの重複をまとめて最大100件を保持します。サーバーから読み込んだ実績も空いている履歴枠に補います。履歴はアカウント別のキャッシュに保存します。
- 履歴・定型のカードをカレンダーへドラッグすると、プロジェクト・アクティビティ・コメント・長さを再利用できます。先に時間範囲を選択した場合は、その長さを優先します。既存ブロックへドロップした場合は時間を保持して、プロジェクト・作業・コメントを置き換えます。入力禁止時間と重複時間は通常の作成と同様に除外します。
- 実績の右クリック →「定型入力に登録…」、履歴カードの右クリック、または「定型」タブの登録ボタンから、繰り返す入力を名前付きで保存できます。定型カードの右クリックで名前変更・削除ができます。自動で定期登録は行いません。
- 履歴・定型の検索は、かな・全半角・空白の違いを吸収します。無効なプロジェクト・アクティビティは表示しません。
- 「★ お気に入りのみ」の切り替えではツリーを全展開せず、開閉状態を保持します。「表示プロジェクト」ではチェック済みを先頭、その中を名前順で表示します。
- 上部「期間…」で開始日・終了日を指定できます。両端を含めて最大31日、1日の幅は100〜400pxです。期間表示は土日を含む連続日付で、下部の横スクロールで移動します。日付見出しも連動します。「週」で通常の週表示に戻ります。同じ期間の列幅変更では通信しません。
- 期間切り替え前には未保存変更を保存します。キャッシュには選択期間と列幅も保持します。週集計のため、取得範囲は両端の週を含めます（最大42日）。右の週集計は選択した日が属する週を集計し、上部は指定期間の合計を表示します。
- 上部「先週と比較」は、表示週（期間表示では統計で選んだ日の週）とその前週を別画面で左右に並べます。元の実績は編集せず、先週からコピーできます。土日を含む7日表示です。縦スクロールが連動し、ホバーで実績詳細を確認できます。先週はサーバーから取得し、表示週には現在の未保存編集を含みます。
- アップデートダイアログに「配布フォルダを開く」を追加しました。更新は保存してアプリを終了後、配布ファイル一式をコピーしてください。実行中の自動置換は行いません。
- 拡大プレビュー確定や選択に伴う再描画で、ドラッグ対象のブロックを操作中に差し替えないよう修正しました。

### 先週のブロックをコピー

「先週と比較」の左側でブロックをクリックすると青枠で選択されます。Ctrl+クリックで複数選択、Shift+クリックで開始時刻順の範囲選択ができます。

1. 「コピーして戻る」を押します（Ctrl+C／「コピー」も使用可能。その場合は画面を閉じてください）。
2. メイン画面で貼り付け先の日時をクリックします。
3. Ctrl+V または上部の貼り付けボタンで配置します。

先頭ブロックが指定位置に配置され、複数ブロック間の日付・時間差、プロジェクト、アクティビティ、コメント、長さを引き継ぎます。先週の実績は変更せず、新しい実績として通常の定期保存対象になります。重複・入力禁止時間を除外し、Ctrl+Zで取り消せます。全ブロックがメイン画面の表示範囲内に収まる位置を指定してください。日をまたぐ実績・5分単位以外の実績や、現在利用できないプロジェクト・アクティビティはコピー対象にできません。
### 5分セルのクリック・範囲選択

空きセルはクリックだけで5分の1セルを選択します。セルの下半分でも次のセルへ丸めず、クリックしたセルを起点にします。上下のドラッグでは起点とカーソル位置のセルを両方含めます。作業のドロップ位置も同じ判定です。Escで選択を解除できます。
